Documentation

World Map Open Source is a thin layer on top of OpenFreeMap (free tiles) + MapLibre. The product is not a tile farm — it is curated GeoJSON overlays, versioned in git, that people and AI agents extend through pull requests.

The basemap is free. Curated layers are the product. We do not reinvent OSM: configure an OpenFreeMap style URL and load FeatureCollections from overlays/. Sample city: Berlin.

Quick start

Integrate a map in three steps: MapLibre + an OpenFreeMap style, then GeoJSON sources for overlays. The SDK in packages/sdk stays thin (load / validate) — you can also copy the pattern from the demo.

1. Serve the repo locally

python3 -m http.server 5173
# Demo:    http://localhost:5173/apps/demo/
# Buses:   http://localhost:5173/apps/transit-demo/
# Trains:  http://localhost:5173/apps/train-demo/
# Docs:  http://localhost:5173/apps/docs/

2. MapLibre + OpenFreeMap

const STYLE_URL = "https://tiles.openfreemap.org/styles/liberty";

const map = new maplibregl.Map({
  container: "map",
  style: STYLE_URL,
  center: [13.405, 52.52], // Berlin
  zoom: 12,
});

3. Load an overlay

map.on("load", async () => {
  const data = await fetch("../../overlays/places/berlin.geojson")
    .then((r) => r.json());

  map.addSource("places", { type: "geojson", data });
  map.addLayer({
    id: "places-circles",
    type: "circle",
    source: "places",
    paint: {
      "circle-radius": 7,
      "circle-color": "#0d6e6e",
      "circle-stroke-width": 1.5,
      "circle-stroke-color": "#fff",
    },
  });
});

Full implementation: apps/demo/ (main.js + overlays-config.js).

Intermediate 2. Multi-layer toggle UI

Load all MVP categories and wire checkboxes to layer visibility (same idea as apps/demo). 

const CATEGORIES = [
  { id: "places",    url: "/overlays/places/berlin.geojson",    color: "#0d6e6e" },
  { id: "nature",    url: "/overlays/nature/berlin.geojson",    color: "#2f7d32" },
  { id: "transport", url: "/overlays/transport/berlin.geojson", color: "#1565c0" },
  { id: "culture",   url: "/overlays/culture/berlin.geojson",   color: "#6a1b9a" },
  { id: "community", url: "/overlays/community/berlin.geojson", color: "#c62828" },
];

map.on("load", async () => {
  for (const cat of CATEGORIES) {
    const data = await fetch(cat.url).then((r) => r.json());
    map.addSource(`src-${cat.id}`, { type: "geojson", data });
    map.addLayer({
      id: `lyr-${cat.id}`,
      type: "circle",
      source: `src-${cat.id}`,
      paint: {
        "circle-radius": 7,
        "circle-color": cat.color,
        "circle-stroke-width": 1.5,
        "circle-stroke-color": "#fff",
      },
    });
  }

  document.querySelectorAll("[data-layer]").forEach((input) => {
    input.addEventListener("change", () => {
      const id = input.dataset.layer;
      map.setLayoutProperty(
        `lyr-${id}`,
        "visibility",
        input.checked ? "visible" : "none"
      );
    });
  });
});

// HTML: <label><input type="checkbox" data-layer="places" checked /> places</label>

Intermediate 3. Filter by kind / tag

Keep one source, filter the layer with MapLibre expressions — e.g. only cafés, or only nature viewpoints. 

// After adding source "places" and layer "places-circles":
function showOnlyKind(kind) {
  map.setFilter("places-circles", kind
    ? ["==", ["get", "kind"], kind]
    : null // clear filter = show all
  );
}

showOnlyKind("cafe");           // only cafés
showOnlyKind("drinking_water"); // only fountains
showOnlyKind(null);             // reset

// Nature viewpoints only:
map.setFilter("lyr-nature", ["==", ["get", "kind"], "viewpoint"]);

Intermediate 4. Custom app overlay (your CDN)

Load community overlays from this repo and your own GeoJSON from your domain — typical for product pages that mix public + private data. 

const COMMUNITY = "/overlays/places/berlin.geojson";
const MY_STORES = "https://cdn.example.com/geo/berlin-stores.geojson";

async function addGeoJsonLayer(map, { id, url, color }) {
  const data = await fetch(url).then((r) => r.json());
  map.addSource(id, { type: "geojson", data });
  map.addLayer({
    id: `${id}-circles`,
    type: "circle",
    source: id,
    paint: {
      "circle-radius": 8,
      "circle-color": color,
      "circle-stroke-width": 2,
      "circle-stroke-color": "#fff",
    },
  });
}

map.on("load", async () => {
  await addGeoJsonLayer(map, { id: "community-places", url: COMMUNITY, color: "#0d6e6e" });
  await addGeoJsonLayer(map, { id: "my-stores", url: MY_STORES, color: "#c45c26" });
});

Intermediate 5. Popup / detail card

Click a feature to show name, id, kind, source, and optional website — attribution-friendly for public maps. 

function bindPopup(map, layerId) {
  map.on("click", layerId, (e) => {
    const f = e.features?.[0];
    if (!f) return;
    const p = f.properties || {};
    const site = p.website
      ? `<br/><a href="${p.website}" target="_blank" rel="noopener">Website</a>`
      : "";
    new maplibregl.Popup()
      .setLngLat(e.lngLat)
      .setHTML(`
        <strong>${p.name ?? "Feature"}</strong><br/>
        <code>${p.id ?? ""}</code><br/>
        ${p.category}/${p.kind}<br/>
        source: ${p.source ?? "—"} · license: ${p.license ?? "—"}
        ${site}
      `)
      .addTo(map);
  });

  map.on("mouseenter", layerId, () => {
    map.getCanvas().style.cursor = "pointer";
  });
  map.on("mouseleave", layerId, () => {
    map.getCanvas().style.cursor = "";
  });
}

bindPopup(map, "places-circles");

Intermediate 6. Fly-to / deep link

Support ?lat=&lon=&zoom= or jump to a feature by ?feature=places/berlin-staatsbibliothek. 

function applyDeepLink(map, featureIndex) {
  const params = new URLSearchParams(location.search);
  const lat = parseFloat(params.get("lat"));
  const lon = parseFloat(params.get("lon"));
  const zoom = parseFloat(params.get("zoom") || "14");
  const featureId = params.get("feature");

  if (Number.isFinite(lat) && Number.isFinite(lon)) {
    map.flyTo({ center: [lon, lat], zoom, essential: true });
    return;
  }

  if (featureId && featureIndex[featureId]) {
    const [lng, lat2] = featureIndex[featureId];
    map.flyTo({ center: [lng, lat2], zoom: 15, essential: true });
  }
}

// Build an id → [lng, lat] index while loading overlays:
const featureIndex = {};
for (const f of data.features) {
  featureIndex[f.properties.id] = f.geometry.coordinates;
}

map.on("load", () => applyDeepLink(map, featureIndex));

// Examples:
//   ?lat=52.52&lon=13.405&zoom=13
//   ?feature=places/berlin-staatsbibliothek

Advanced 7. React / Next sketch

Thin client component: mount MapLibre once, load Berlin places on load. Works in Next.js with "use client". 

"use client";
import { useEffect, useRef } from "react";
import maplibregl from "maplibre-gl";
import "maplibre-gl/dist/maplibre-gl.css";

const STYLE = "https://tiles.openfreemap.org/styles/liberty";
const PLACES = "/overlays/places/berlin.geojson";

export function BerlinMap() {
  const ref = useRef(null);

  useEffect(() => {
    if (!ref.current) return;
    const map = new maplibregl.Map({
      container: ref.current,
      style: STYLE,
      center: [13.405, 52.52],
      zoom: 12,
    });

    map.on("load", async () => {
      const data = await fetch(PLACES).then((r) => r.json());
      map.addSource("places", { type: "geojson", data });
      map.addLayer({
        id: "places",
        type: "circle",
        source: "places",
        paint: {
          "circle-radius": 7,
          "circle-color": "#0d6e6e",
          "circle-stroke-width": 1.5,
          "circle-stroke-color": "#fff",
        },
      });
    });

    return () => map.remove();
  }, []);

  return <div ref={ref} style={{ width: "100%", height: "480px" }} />;
}

Advanced 9. Basemap + private business locations (store locator)

Pattern for a company page: free OpenFreeMap base, public community context optional, and your private store GeoJSON with a sidebar list that flies to the selected pin. 

const STORES = {
  type: "FeatureCollection",
  features: [
    {
      type: "Feature",
      geometry: { type: "Point", coordinates: [13.388, 52.517] },
      properties: {
        id: "store/berlin-mitte",
        name: "Flagship — Mitte",
        hours: "10:00–20:00",
        category: "stores",
      },
    },
    {
      type: "Feature",
      geometry: { type: "Point", coordinates: [13.455, 52.501] },
      properties: {
        id: "store/berlin-kreuzberg",
        name: "Shop — Kreuzberg",
        hours: "11:00–19:00",
        category: "stores",
      },
    },
  ],
};

map.on("load", () => {
  map.addSource("stores", { type: "geojson", data: STORES });
  map.addLayer({
    id: "stores",
    type: "circle",
    source: "stores",
    paint: {
      "circle-radius": 10,
      "circle-color": "#c45c26",
      "circle-stroke-width": 2,
      "circle-stroke-color": "#fff",
    },
  });

  const list = document.getElementById("store-list");
  for (const f of STORES.features) {
    const li = document.createElement("li");
    li.textContent = `${f.properties.name} · ${f.properties.hours}`;
    li.tabIndex = 0;
    li.addEventListener("click", () => {
      map.flyTo({ center: f.geometry.coordinates, zoom: 15 });
    });
    list.appendChild(li);
  }
});

How agents contribute to the map

The repo is the API: agents do not write to a separate database — they load overlays from git/Pages, or add files under overlays/{category}/ and open a pull request.

Show vs add. To put the map in your own demo, load overlays/manifest.json or open apps/embed/ (MCP: get_embed_snippet) — no PR. To add pins, validate + open a PR — never silent-push to main. After merge, Pages updates in ~1–3 minutes; your next fetch sees new data without rebuilding your site.

Workflow (step by step)

  1. Read CONTRIBUTING.md and docs/PLAN.md.
  2. Pick an MVP category: places · nature · transport · culture · community.
  3. Add / edit overlays/<category>/<dataset>.geojson (+ optional .meta.yaml).
  4. Validate against schemas/overlay.schema.json and kinds in schemas/taxonomy.json (CI runs the same check).
  5. Open a PR — for community mark draft / needs-human-review.
  6. After merge the overlay lives on git; the demo loads Berlin files from overlays/<category>/berlin.geojson.

File conventions

overlays/
  places/
    berlin.geojson   # FeatureCollection (required)
    berlin.meta.yaml # dataset metadata (recommended)
    README.md        # kinds + category scope
schemas/
  taxonomy.json      # kinds + review_policy (agents + future MCP)
  overlay.schema.json

Each .geojson is a FeatureCollection. The companion .meta.yaml describes provenance / city / notes for reviewers (not yet validated by CI). 

# berlin.meta.yaml
id: places-berlin
category: places
city: Berlin
license: ODbL-1.0
notes: Curated amenity pins for the MapLibre demo.

Stable IDs

Every feature has a repo-wide unique properties.id. MVP format: 

{category}/{city}-{slug}
# e.g. places/berlin-brandenburg-gate-drinking-water
#      community/berlin-kreuzberg-repair-cafe

kebab-case, no spaces. The schema allows separators /, _, -. For future apps, namespaces will live under overlays/_ns/<app-id>/.

Minimal example (copy-paste for agents)

{
  "type": "FeatureCollection",
  "name": "places-berlin",
  "features": [
    {
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [13.3777, 52.5163]
      },
      "properties": {
        "id": "places/berlin-brandenburg-gate-drinking-water",
        "name": "Drinking fountain — Brandenburg Gate",
        "category": "places",
        "kind": "drinking_water",
        "source": "agent",
        "verified_at": "2026-03-20",
        "license": "ODbL-1.0",
        "extra": { "city": "Berlin" }
      }
    }
  ]
}
  • GeoJSON coordinates: [longitude, latitude]
  • Required fields: id, name, category, kind, source, license
  • category = parent folder name
  • AI drafts: source: "agent"

Validation & CI

Workflow .github/workflows/validate-overlays.yml runs on PRs:

  • Every overlays/**/*.geojson must pass schemas/overlay.schema.json (including kind allow-lists per category)
  • properties.id unique across the whole repo
  • Local (optional): npm install --no-save ajv@8 ajv-formats@3 && node scripts/validate-overlays.mjs
  • SDK helpers: validateFeature / validateFeatureCollection in packages/sdk

What agents must NOT do

  • Do not host or copy planetary tiles / OSM dumps into the repo
  • Do not invent a parallel “OSM-like” database — curated overlays only
  • Do not force-push main
  • Do not auto-merge community (or future hazards) — draft + human review only
  • Do not store PII (private phones, home addresses)
  • Do not commit / push without the user’s explicit request

Human contributions

Same model as for agents: edit GeoJSON under overlays/, open a PR, CI validates. Detailed steps in CONTRIBUTING.md.

  1. Pick a category folder
  2. Add a feature with id, name, category, kind, source, license
  3. For community: label needs-human-review
