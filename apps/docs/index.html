Documentație

World Map Open Source este un strat subțire peste OpenFreeMap (dale libere) + MapLibre. Produsul nu e un tile farm — sunt overlay-uri GeoJSON curate, versionate pe git, pe care oamenii și agenții AI le completează prin PR.

Baza e gratuită. Straturile curate sunt produsul. Nu reinventăm OSM: configurăm un style URL OpenFreeMap și încărcăm FeatureCollection-uri din overlays/.

Cum se aplică / Quick start

Integrezi harta în trei pași: MapLibre + style OpenFreeMap, apoi surse GeoJSON pentru overlay-uri. SDK-ul din packages/sdk rămâne subțire (load / validate) — încă poți copia pattern-ul din demo.

1. Servește repo-ul local

python3 -m http.server 5173
# Demo:  http://localhost:5173/apps/demo/
# Docs:  http://localhost:5173/apps/docs/

2. MapLibre + OpenFreeMap

const STYLE_URL = "https://tiles.openfreemap.org/styles/liberty";

const map = new maplibregl.Map({
  container: "map",
  style: STYLE_URL,
  center: [26.1, 44.43], // București
  zoom: 12,
});

3. Încarcă un overlay

map.on("load", async () => {
  const data = await fetch("../../overlays/places/sample-bucharest.geojson")
    .then((r) => r.json());

  map.addSource("places", { type: "geojson", data });
  map.addLayer({
    id: "places-circles",
    type: "circle",
    source: "places",
    paint: {
      "circle-radius": 7,
      "circle-color": "#0d6e6e",
      "circle-stroke-width": 1.5,
      "circle-stroke-color": "#fff",
    },
  });
});

Vezi implementarea completă în apps/demo/ (main.js + overlays-config.js).

Cum completează agenții harta

Repo-ul este API-ul: agenții nu scriu într-o bază separată — adaugă / editează fișiere sub overlays/{category}/ și deschid un pull request. După merge + CI verde, punctele apar pe demo.

Workflow (pas cu pas)

  1. Citește skill-ul — .cursor/skills/add-overlay/ (SKILL.md + reference.md + examples.md).
  2. Alege categoria MVP: places · nature · transport · culture · community.
  3. Adaugă / editează overlays/<category>/<dataset>.geojson (+ opțional .meta.yaml).
  4. Validează față de schemas/overlay.schema.json (CI face același check).
  5. Deschide PR — pentru community marchează draft / needs-human-review.
  6. După merge overlay-ul e pe git; demo-ul îl încarcă din path-urile din manifest.

Convenții de fișiere

overlays/
  places/
    sample-bucharest.geojson   # FeatureCollection (obligatoriu)
    sample-bucharest.meta.yaml # metadate dataset (recomandat)
    README.md                  # kinds + scop categorie

Fiecare .geojson e un FeatureCollection. Companionul .meta.yaml descrie provenance / city / note pentru revieweri (nu e încă validat de CI). 

# sample-bucharest.meta.yaml
id: places-bucharest-sample
category: places
city: Bucharest
license: ODbL-1.0
notes: Sample pins for the MapLibre demo.

ID stabil

Fiecare feature are properties.id unic în tot repo-ul. Format MVP (namespace = categorie): 

{category}/{slug}
# ex: places/bucharest-cismigiu-drinking-water
#     community/bucharest-repair-cafe-draft

kebab-case, fără spații. Schema acceptă separatorii /, _, -. Pentru app-uri viitoare, namespace-urile vor trăi sub overlays/_ns/<app-id>/.

Exemplu minimal (copy-paste pentru agent)

{
  "type": "FeatureCollection",
  "name": "places-my-city",
  "features": [
    {
      "type": "Feature",
      "geometry": {
        "type": "Point",
        "coordinates": [26.0910, 44.4368]
      },
      "properties": {
        "id": "places/bucharest-cismigiu-drinking-water",
        "name": "Drinking fountain — Cișmigiu",
        "category": "places",
        "kind": "drinking_water",
        "source": "agent",
        "verified_at": "2026-03-20",
        "license": "ODbL-1.0",
        "extra": { "city": "Bucharest" }
      }
    }
  ]
}
  • Coordonate GeoJSON: [longitude, latitude]
  • Câmpuri obligatorii: id, name, category, kind, source, license
  • category = numele folderului părinte
  • Drafturi AI: source: "agent"

Validare & CI

Workflow-ul .github/workflows/validate-overlays.yml rulează pe PR:

  • Fiecare overlays/**/*.geojson trebuie să treacă schemas/overlay.schema.json
  • properties.id unic în tot repo-ul
  • Local (opțional): npx --yes ajv-cli validate -s schemas/overlay.schema.json -d "overlays/**/*.geojson"

Ce agenții NU trebuie să facă

  • Nu hosta / nu copia dale planetare sau dump-uri OSM în repo
  • Nu inventa o bază paralelă „OSM-like” — doar overlay-uri curate
  • Nu face force-push pe main
  • Nu merge automat community (sau viitorul hazards) — doar draft + review uman
  • Nu stoca PII (telefoane private, adrese de casă)
  • Nu commit / push fără cererea explicită a utilizatorului

Contribuții umane

Același model ca pentru agenți: editezi GeoJSON sub overlays/, deschizi PR, CI validează. Vezi pașii detaliați în CONTRIBUTING.md.

  1. Alege folderul de categorie
  2. Adaugă feature cu id, name, category, kind, source, license
  3. Pentru community: label needs-human-review
